# Master Implementation Plan

Owner: Bianca Romero (product owner). Orchestrator: Claude main session. Workers: W0–W3, one per repo, running in parallel.
Decision date: 2026-10-28. All decisions are recorded in `docs/adr/`. Workers do not re-open decided questions.

## 1. Principles

1. **Autonomy.** Workers never ask the owner. If a spec is ambiguous, the worker chooses the option that is simpler, cheaper and better documented, writes an ADR in its repo, and moves on.
2. **Docs are part of the deliverable.** Every PR touches docs. Every architectural choice has an ADR. Every repo has a C4 diagram, an OpenAPI spec, a runbook, and a README anyone can follow in 3 commands.
3. **Demo or it did not happen.** Every project ends with a public URL, a 30–60 s GIF in the README, and a case-study page in the portfolio.
4. **Zero paid services.** See ADR-0004. If a free tier disappears, the worker swaps the adapter and documents it.
5. **Same conventions everywhere.** Same monorepo layout, same tooling, same CI, same doc structure. A recruiter who reads one repo understands the other three.

## 3. Shared stack (ADR-0002, ADR-0003)

- Node 20 LTS (>= 20.13), pnpm 9 via corepack, TypeScript 5 strict, ESM.
- Monorepo per repo with **Turborepo**: `apps/web` (Next.js 16, App Router), `apps/api` (NestJS 11), `packages/shared` (zod schemas, DTOs, event contracts), `packages/config` (eslint, tsconfig, prettier). Extra apps per spec.
- Postgres 16 everywhere. Prisma (latest stable) as ORM. Migrations committed.
- Validation: zod at every boundary (HTTP, queue, env). Env parsed once in `packages/shared/env.ts`; app crashes on invalid env.
- Auth: Supabase Auth (ledgerflow, incident-copilot) validated by a NestJS guard using the Supabase JWT secret / JWKS. pulse uses tenant API keys + Auth.js (GitHub provider) for the dashboard (ADR-0006).
- Tests: Vitest (unit, >= 70% lines on domain packages), Supertest (API), Playwright (web e2e, smoke on CI), fast-check for invariants where the spec says so.
- Lint/format: ESLint flat config + Prettier. Commit lint: conventional commits via commitlint + husky. Changelog: release-please GitHub Action.
- CI: GitHub Actions `ci.yml` (install, lint, typecheck, test, build, docker build) on PR and main. Required to merge (self-enforced; no branch protection needed).
- Docker: multi-stage Dockerfile per app, `docker compose up` brings the full local stack with seed data.
- Observability baseline: pino structured logs with request id in all APIs. OpenTelemetry full stack only in pulse (ADR-0008).
- Hosting (ADR-0004): web on Vercel; APIs on Render free (Docker web service); DB on Supabase free (ledgerflow, incident-copilot) and Neon free (pulse); Upstash Redis free for pulse hosted transport.

## 6. Worker protocol

1. Read, in order: this file, `docs/adr/*`, your spec, `templates/CLAUDE.template.md`, your repo's `CLAUDE.md`.
2. For the current phase, make sure every task in the spec has a GitHub issue (`gh issue create`), labelled `phase:N` and `area:<web|api|infra|docs>`. One issue per task ID. Put the task ID in the title (`[P1-03] Prisma schema and first migration`).
3. Per task: branch `feat/<issue-number>-<slug>` (or `fix/`, `chore/`, `docs/`). Small commits, conventional messages, body explains *why*.
4. Open PR with the template fully filled. Link the issue (`Closes #N`). Wait for CI. Squash merge. Delete branch. PR title becomes the changelog line, so write it for a reader.
5. Docs in the same PR. If you changed a decision, add an ADR and update `decisions-log.md`.
6. Never commit secrets. `.env.example` always complete. Use `gh secret set` for CI secrets if needed.
7. If blocked by something only the owner can do (create an external account), write it to `docs/BLOCKED.md` with exact steps, keep working on everything else, and mention it in your end-of-phase report.
8. End of phase: open an issue titled `Phase N report` with: what shipped (PR links), what was deferred, ADRs written, known issues, metrics (coverage, Lighthouse, test counts), and the next-phase plan. The orchestrator reviews it against the gate checklist.
9. Verify claims. "Tests pass" means you ran them and pasted the summary in the PR. "Deployed" means you opened the URL.
10. Language: English in code, commits, docs, UI default locale. Spanish only in README "Español" section and in the portfolio's `es` locale.
